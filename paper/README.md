# Paper

Quarto source for the PINN-pricing paper.

## Render

From the project root:

```bash
# One command refreshes the master table AND every figure
bash paper/sync_artifacts.sh

# Build the PDF
quarto render paper/paper.qmd --to pdf

# Or HTML draft for sharing
quarto render paper/paper.qmd --to html
```

The PDF lands in `paper/_output/paper.pdf` (configured in `_quarto.yml`).
The intermediate `paper.tex` is kept alongside the PDF for inspection.

## Figure pipeline

`paper/scripts/generate_figures.py` produces the matplotlib figures
referenced by the .qmd:

| Figure | Source data | Notes |
|--------|-------------|-------|
| `fig-architecture.png` | hand-laid (matplotlib) | TikZ alternative at `figures/architecture.tex` |
| `fig-walkforward-timeline.png` | `FOLDS` list (static) | always renders |
| `fig-arb-rmse-pareto.png` | `reports/master_table.csv` | needs build_master_table |
| `fig-stratified-rmse.png` | `reports/master_table.csv` | needs build_master_table |
| `fig-loss-curves-stability.png` | `runs/walk_forward_history/{B6,B10}/fold_Nov2020.pt` | needs SLURM rerun (`slurm/run_history_capture.sh`) |
| `fig-weight-traj-stability.png` | same | same |
| `fig-pde-dominance.png` | same | same |
| `fig-val-curve-mu-warmup.png` | history for B10/B11/B12 on Nov2020 | needs additional reruns |

Figures whose source data isn't there yet **skip cleanly** instead of
failing the build — `paper.qmd` already renders against any subset.

## Structure

```
paper/
  _quarto.yml          ← format/cache/bib config
  paper.qmd            ← document source
  references.bib       ← BibTeX entries
  sync_artifacts.sh    ← copies figures from runs/ into figures/
  figures/             ← .png files referenced by the .qmd
  tables/              ← reserved for hand-curated .tex tables
  _output/             ← rendered PDF/HTML (gitignored)
```

## How tables stay in sync with results

All headline tables in the document are generated by Python chunks
that read `reports/master_table.csv` (built by
`scripts/build_master_table.py`) and `runs/stage2_*/*/results.json`
directly. There is no copy-paste of numbers into the prose. Re-run
the master-table builder after every benchmark refresh and the next
render will reflect the latest numbers automatically.

## How figures get there

`sync_artifacts.sh` is intentionally minimal: it picks the specific
fold-level plots the paper references and copies them into
`figures/` with paper-friendly names (`stage2_vol_surface_B12_cvol_Nov2020.png`,
etc). Edit the script when you want to reference a different fold or
config.

## Adding a new section

1. Drop a new `# Section title {#sec-foo}` heading in `paper.qmd`.
2. If it needs a generated table or plot, add a `{python}` code chunk
   with `#| label: ...` and `#| tbl-cap: ...` (or `fig-cap`).
3. Cross-reference with `Section [-@sec-foo]` in prose.
4. Cite with `[@bibkey]`.

## Why Quarto and not raw LaTeX

* Tables update automatically when results change — the worst kind of
  paper bug (stale numbers) is impossible by construction.
* Markdown prose is much faster to draft than `\begin{...}` LaTeX.
* Bibliography, cross-references, and equations are all handled
  natively.
* If a journal demands `.tex`, `keep-tex: true` in `_quarto.yml`
  leaves a clean `paper.tex` for submission.
